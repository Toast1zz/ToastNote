## 1. 产品定位

ToastNote 是一个原生 macOS Markdown 笔记应用。它只做两件核心的事：

1. **写 Markdown 笔记**：实时渲染，写起来像 Typora / Obsidian Live Preview。
2. **AI 一键排版**：用户只管写内容，按一下快捷键，用自己的 API Key（BYOK）调用大模型，把杂乱的文字整理成结构清晰的 Markdown，**不改写任何措辞**。

### 1.1 “轻量”的定义

“轻量”指**资源占用低**，不是功能少。所有功能都必须在第 3 节的资源预算内实现。

### 1.2 设计原则

1. **原生且美观**：遵循 Apple Human Interface Guidelines，以 macOS 26 的 Liquid Glass 为视觉基准。
2. **内容优先**：控件只在需要时出现，界面让位于文字。
3. **文字胜过图标**：笔记永远只用标题表示，不使用笔记图标或 emoji。SF Symbols 只用于系统级元素（文件夹、置顶、搜索等），并且旁边一定带文字。工具栏按钮这类 macOS 惯例只放图标的控件例外，但必须有 tooltip 和辅助功能标签。
4. **文件就是数据**：笔记是磁盘上的普通 `.md` 文件，可以和 Obsidian、iCloud Drive、Git 共用同一个文件夹。
5. **AI 不碰内容**：AI 只改结构，程序会校验，用户最终确认。
6. **不依赖 Apple Intelligence**：用户使用国行 Mac，所有功能都不能依赖 Apple Intelligence 或 Foundation Models。可以“可选支持”，不能“依赖”。

### 1.3 目标用户

开发者本人，以及在 GitHub 上下载使用的用户。MIT 协议开源。

## 2. 范围

### 2.1 v1 包含

| 功能 | 说明 |
|---|---|
| 笔记库（Vault） | 打开任意文件夹作为笔记库，读写其中的 `.md` 文件 |
| Arc 式侧边栏 | 置顶、已打开（垂直标签）、文件夹、标签四个分区 |
| 实时渲染编辑器 | 光标所在的块显示原始符号，其他块隐藏符号、显示效果 |
| AI 排版 | BYOK，支持 Anthropic 和 OpenAI 兼容接口，带内容校验和左右对比确认 |
| 标签 | 行内 `#标签` 和 frontmatter `tags`，侧边栏可按标签浏览 |
| 全文搜索 | SQLite FTS5，支持中文 |
| 导出 PDF | 按编辑器的阅读排版导出，分页 |
| 粘贴图片 | 图片存进笔记库，编辑器内联显示 |
| 自动更新 | Sparkle 2，更新源放在 GitHub Releases |
| 快速打开 | `⌘P`，按标题和路径模糊匹配 |
| 自动保存、外部修改监听 | 见第 6 节 |
| 专注写作模式 | 隐藏侧边栏和工具栏，只留文字 |

### 2.2 后续阶段（v1 只预留接口）

- **AI 自动关联与关系图谱**：AI 读完所有笔记后，自动发现笔记之间的关系，给出“相关笔记”和关系图谱，用户不需要手动写 `[[链接]]`。详见第 12 节。

### 2.3 v1 明确不做

插件系统、多窗口、iCloud 或自有同步服务、手动 `[[双链]]` 语法、AI 流式输出、iPad 或 iPhone 版本。

## 3. 资源预算（硬性指标）

每个阶段结束时都要实测并记录到 `docs/perf-log.md`。超出预算视为未完成。

| 指标 | 目标 | 测量方法 |
|---|---|---|
| 安装包（DMG） | < 15 MB | Release 构建后看 DMG 文件大小 |
| `.app` 解压后体积 | < 30 MB | `du -sh ToastNote.app` |
| 冷启动到可输入 | < 0.5 秒 | 用 `os_signpost` 标记从启动到编辑器第一响应者就绪的时间 |
| 空闲内存 | < 100 MB | 打开 1000 篇笔记的测试库，打开 5 个标签后静置 30 秒，在活动监视器里看“内存” |
| 空闲 CPU | ≈ 0% | 静置 60 秒，Instruments 的 Time Profiler 里没有周期性唤醒 |
| 输入延迟 | 无可感知卡顿 | 在 1 万字的文档里连续输入，单次按键处理 < 8ms（signpost 测量） |
| 首次建立索引 | 1000 篇笔记 < 5 秒 | 在后台低优先级完成，不阻塞界面 |

为了守住预算，有以下实现约束：

- **外部依赖只有两个**：`swift-markdown`（Apple 官方，内含 cmark-gfm）和 `Sparkle`。新增任何依赖都必须先在 spec 里论证。
- **不用 WebView 渲染界面**。只有导出 PDF 时才临时创建 `WKWebView`，导出完成后立即释放。
- **不轮询**：文件变化用 FSEvents，不用定时器检查。
- **图片按需解码**：用 ImageIO 生成缩略图，按显示尺寸解码，缓存放在有大小上限的 `NSCache` 里。
- **索引放在应用支持目录**，不放进笔记库，避免同步冲突。

## 4. 平台与工程

### 4.1 平台

- 最低支持 **macOS 14 Sonoma**，视觉以 **macOS 26** 为基准，旧系统降级（见 9.1 节）。
- Swift 6，开启严格并发检查。
- 界面外壳用 SwiftUI，编辑器内核用 AppKit（`NSTextView`，TextKit 1）。

### 4.2 不开启 App Sandbox

v1 只通过 GitHub 分发，不上架 App Store。App Sandbox 会让 Sparkle 的安装流程和笔记库目录访问都变复杂，却带不来分发上的好处，所以**不开启沙盒**，只开启 Hardened Runtime，以便以后公证。

> 注：之前讨论时提过开启沙盒，写 spec 时重新评估后改成了不开。以后如果要上架 App Store，需要另立一个子项目来处理。

### 4.3 工程结构

```
ToastNote/
├── project.yml                  # XcodeGen 配置
├── App/                         # macOS App target（SwiftUI 外壳）
│   ├── ToastNoteApp.swift
│   ├── Views/                   # 侧边栏、编辑器容器、对比窗口、设置等
│   ├── Resources/               # Assets、导出 PDF 用的 CSS、Info.plist
│   └── ToastNote.entitlements
├── Packages/ToastNoteKit/       # 本地 Swift Package，业务逻辑都在这里
│   ├── Package.swift
│   ├── Sources/
│   │   ├── VaultKit/            # 文件、监听、工作区状态
│   │   ├── IndexKit/            # SQLite：标签、全文搜索、预留的向量表
│   │   ├── EditorKit/           # Markdown 解析、样式计算、编辑器视图
│   │   ├── AIFormatKit/         # 服务商、提示词、保护、校验、块差异
│   │   └── ExportKit/           # Markdown → HTML → PDF
│   └── Tests/                   # 每个模块对应一个测试 target
├── docs/
└── .github/workflows/           # CI 与发布
```

- 用 **XcodeGen** 根据 `project.yml` 生成 `.xcodeproj`，`.xcodeproj` 不提交到仓库。
- 构建命令：`xcodegen generate && xcodebuild -scheme ToastNote -configuration Debug build`。
- 测试命令：`swift test --package-path Packages/ToastNoteKit`。
- 测试框架用 Swift Testing（`import Testing`）。

### 4.4 模块依赖

```
App → VaultKit, IndexKit, EditorKit, AIFormatKit, ExportKit
IndexKit → VaultKit（只用到 Note 模型）
AIFormatKit → EditorKit（只用到 Markdown 解析和块模型）
ExportKit → EditorKit（只用到 Markdown 解析）
VaultKit、EditorKit 不依赖其他模块
```

模块之间只通过 `public` 的协议和值类型交互，`public` 的 API 尽量少。

## 5. 数据与存储

### 5.1 笔记库

- 笔记库就是用户选择的任意文件夹。
- 识别 `.md` 和 `.markdown` 文件，其他文件只在文件夹树里隐藏，不做处理。
- 忽略以 `.` 开头的文件和文件夹（包括 `.obsidian`、`.git`、`.toastnote`）。
- 笔记标题 = 文件名去掉扩展名。v1 不从 H1 推断标题。
- 编码统一为 UTF-8。读取时兼容 CRLF，保存时统一写成 LF。
- 写入采用原子写（先写临时文件再替换），保留文件原有的权限。

### 5.2 状态存放位置

| 数据 | 位置 | 原因 |
|---|---|---|
| 置顶列表 | `<笔记库>/.toastnote/workspace.json` | 跟着笔记库走，可以同步到其他设备 |
| 已打开的标签及顺序、当前标签、侧边栏分区的折叠状态 | `~/Library/Application Support/ToastNote/Vaults/<vaultID>/session.json` | 只属于这台设备 |
| 索引数据库 | `~/Library/Application Support/ToastNote/Vaults/<vaultID>/index.sqlite` | 可以随时重建，不该同步 |
| 应用设置 | `UserDefaults` | 系统惯例 |
| API Key | 钥匙串（`kSecClassGenericPassword`，service 为 `app.toastnote.ai`，account 为服务商 ID） | 安全 |

- `vaultID` = 笔记库绝对路径的 SHA-256 前 16 位十六进制。
- 最近打开的笔记库列表存在 `UserDefaults`，最多 10 个。
- `workspace.json` 格式：`{"version":1,"pinned":["相对路径.md", ...]}`。

### 5.3 索引数据库结构（IndexKit）

```sql
CREATE TABLE notes (
  id        INTEGER PRIMARY KEY,
  path      TEXT NOT NULL UNIQUE,   -- 相对笔记库的路径
  title     TEXT NOT NULL,
  body      TEXT NOT NULL,          -- 去掉 frontmatter 后的纯文本，用于搜索和短查询
  mtime     REAL NOT NULL,
  size      INTEGER NOT NULL
);
CREATE VIRTUAL TABLE notes_fts USING fts5(
  title, body, content='notes', content_rowid='id', tokenize='trigram'
);
CREATE TABLE tags (
  note_id INTEGER NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
  tag     TEXT NOT NULL,            -- 保存时去掉 #，比较时不区分大小写
  PRIMARY KEY (note_id, tag)
);
CREATE INDEX tags_tag ON tags(tag COLLATE NOCASE);

-- 预留给后续的 AI 关联功能，v1 只建表不写入
CREATE TABLE embeddings (
  note_id  INTEGER NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
  chunk    INTEGER NOT NULL,
  model    TEXT NOT NULL,
  vector   BLOB NOT NULL,           -- Float32 小端序
  PRIMARY KEY (note_id, chunk, model)
);
CREATE TABLE meta (key TEXT PRIMARY KEY, value TEXT);  -- schema_version 等
```

- 用系统自带的 `libsqlite3`（`import SQLite3`），自己写一个很薄的封装，不引入第三方 SQLite 库。
- 打开数据库时设置 `PRAGMA journal_mode=WAL`、`PRAGMA foreign_keys=ON`。
- 通过 `notes` 表上的触发器同步 `notes_fts`（FTS5 外部内容表的标准写法）。
- `schema_version` 不一致时，删除数据库并重建索引。
- 启动时比较每个文件的 `mtime` 和 `size`，只重新索引有变化的文件。
- 索引在后台 actor 上进行，优先级为 `.utility`。

## 6. 笔记库服务（VaultKit）

### 6.1 职责

- 扫描笔记库，生成文件夹树（`FolderNode`、`NoteRef` 值类型）。
- 读写笔记（原子写）。
- 新建、重命名、移动笔记和文件夹；删除时用 `NSWorkspace.recycle` 移到废纸篓，**不做永久删除**。
- 用 FSEvents 监听笔记库（`kFSEventStreamCreateFlagFileEvents`，延迟 0.3 秒），向外发出 `VaultChange` 事件。
- 读写 `workspace.json` 和 `session.json`。

### 6.2 自动保存

- 输入停止 1 秒后保存；切换标签、关闭标签、应用失去焦点、退出时立即保存。
- `⌘S` 立即保存（虽然有自动保存，但保留用户习惯）。
- 内容没有变化时不写盘。
- 记录自己写入的文件路径和写入后的修改时间，FSEvents 收到对应事件时忽略，避免“自己改的文件被当作外部修改”。

### 6.3 外部修改

| 情况 | 行为 |
|---|---|
| 打开的笔记被外部修改，本地没有未保存的改动 | 直接重新载入，尽量保持光标和滚动位置 |
| 打开的笔记被外部修改，本地有未保存的改动 | 编辑器顶部显示横幅：“此笔记已在其他地方被修改”，按钮为“载入新版本”和“保留我的版本”。选“保留”后，下次保存时覆盖磁盘内容 |
| 打开的笔记被外部删除 | 横幅：“此笔记已被删除”，按钮为“重新保存”和“关闭”。 |
| 打开的笔记被外部重命名 | FSEvents 能识别为重命名时更新标签路径；识别不了时按“删除”处理 |

### 6.4 新建笔记

- `⌘N` 在当前选中的文件夹里新建（没有选中时放在根目录），文件名是“未命名”，重名时加序号，例如“未命名 2”。
- 新笔记立即打开为标签，光标放在正文开头。
- 文件名**不会**根据正文内容自动修改。重命名只能手动操作：在侧边栏里双击或右键选“重命名”，或点击窗口标题。

## 7. 编辑器（EditorKit）

### 7.1 架构

```
文本（String）
  → MarkdownParser（swift-markdown，得到带源码位置的语法树）
  → BlockModel（把语法树拍平为顶层块列表：类型、范围、内部各种符号的范围）
  → MarkdownStyler（纯函数：输入 BlockModel、活动块集合、主题，输出样式片段列表）
  → MarkdownTextView（NSTextView 子类：应用样式、隐藏符号、处理交互）
```

- `MarkdownStyler` 是纯函数，不依赖 AppKit 的视图，单元测试主要覆盖它。
- 样式片段格式：`[(NSRange, StyleAttributes)]`，以及需要隐藏的符号范围 `[NSRange]`。

### 7.2 块与活动块

- **块**：顶层块级元素，包括段落、标题、引用、代码块、表格、分割线、frontmatter。列表比较特殊，**列表中的每一项各自算一个块**。
- **活动块**：光标或选区所在的块。选区跨多个块时，这些块都是活动块。
- **活动块显示原始 Markdown 符号**（符号用次要颜色显示，但样式照常，比如标题仍是大字号）；**非活动块隐藏符号**。
- 隐藏的实现方式：在 `NSLayoutManagerDelegate.layoutManager(_:shouldGenerateGlyphs:properties:characterIndexes:font:forGlyphRange:)` 里，把需要隐藏的字符的字形属性设为 `.null`。**不用**“把字号设成极小”或“设成透明色”这种做法。
- 光标移动只会改变活动块，因此只需要让新旧活动块的字形失效重新布局，不要整篇重新应用样式。

### 7.3 各元素的渲染规则

| 元素 | 非活动块的效果 | 被隐藏的符号 |
|---|---|---|
| 标题 H1–H6 | 字号与字重见 9.3 节 | `#` 和后面的空格 |
| 粗体、斜体、粗斜体 | 加粗、斜体 | `**`、`*`、`__`、`_` |
| 删除线 | 删除线 | `~~` |
| 行内代码 | 等宽字体加圆角背景 | 两侧的反引号 |
| 链接 `[文字](URL)` | 只显示“文字”，用强调色；`⌘` + 点击用浏览器打开 | `[`、`](URL)` |
| 裸 URL | 强调色，`⌘` + 点击打开 | 无 |
| 无序列表 | 圆点 `•`（用自定义绘制替代 `-`/`*`/`+`） | 原始符号被替换显示 |
| 有序列表 | 保留数字，数字用次要颜色 | 无 |
| 任务列表 | 绘制复选框，点击切换 `[ ]` / `[x]`，已完成的项文字变为次要颜色加删除线 | `- [ ]`、`- [x]` |
| 引用 | 左侧 3pt 圆角竖线（强调色，40% 不透明度），文字用次要颜色 | `>` 和后面的空格 |
| 代码块 | 等宽字体，整块圆角背景，右上角用小字显示语言名。**不做语法高亮** | 首尾的 ``` 行 |
| 分割线 | 一条细线 | `---` |
| 表格 | **v1 只高亮不渲染**：等宽字体，`|` 和分隔行用次要颜色 | 无 |
| 图片 `![](路径)` | 在该行下方内联显示图片，最大宽度为正文宽度 | 整行语法 |
| 标签 `#标签` | 强调色文字加 12% 不透明度的胶囊背景 | 无 |
| frontmatter | 整块折叠成一行，显示“属性 · N 项”，用次要颜色；进入活动状态时展开 | 非活动时整块隐藏 |

### 7.4 解析与性能

- 每次编辑后同步重新解析全文，并用 signpost 测量耗时。
- 如果单次解析加样式计算超过 4ms，改为对“被编辑的块”立刻局部重新上样式，再在 150ms 防抖后完整解析一次。这个优化只在实测超标时才做。
- **输入法组字期间（`hasMarkedText()` 为真）不重新上样式**，组字结束后再处理。这是中文输入的硬性要求，必须有测试覆盖。
- 撤销和重做由 `NSTextView` 自带的 undo manager 处理，重新上样式不能产生撤销记录（只改属性时用 `textStorage.beginEditing()` 包住，并且不注册撤销）。

### 7.5 编辑快捷操作

- `⌘B` 粗体、`⌘I` 斜体、`⌘K` 插入链接、`⌘⇧X` 删除线、`⌘E` 行内代码：有选中内容时包裹或取消包裹，没有选中时插入一对符号并把光标放在中间。
- 在列表项末尾回车：自动续写下一项（有序列表自动加一，任务列表续写 `- [ ] `）；在空列表项上回车：退出列表。
- `Tab` / `⇧Tab` 在列表项上缩进或取消缩进。
- 粘贴来自网页的富文本时：只粘贴纯文本（`⌘⇧⌥V` 例外，遵循系统惯例）。v1 不做 HTML → Markdown 转换，那是 AI 排版的活。

### 7.6 只读渲染模式

`MarkdownTextView` 提供 `concealAll` 模式：不可编辑，没有活动块，所有符号都隐藏。AI 对比窗口的两栏都用这个模式（见 8.6 节），保证看到的和接受后在编辑器里看到的一致。

## 8. AI 排版（AIFormatKit）

### 8.1 流程

```
用户按 ⌘⇧L
 → 确定范围：有选中内容时只处理选中部分，否则处理全文
 → Protector：把 frontmatter、代码块、行内代码、链接 URL、图片语法替换成占位符
 → Chunker：超过约 6000 字时，按标题或空行拆成多段
 → Provider：逐段调用大模型（不流式），可以取消
 → Protector：还原占位符；任何一个占位符缺失或重复，判为失败
 → ContentGuard：校验文字内容是否被修改
 → BlockDiff：计算哪些块的结构发生了变化
 → 打开对比窗口，用户选择接受或放弃
 → 接受：在一个撤销组里替换文本，撤销名称为“AI 排版”
```

### 8.2 服务商

两种适配器，都直接用 `URLSession`，不引入任何 SDK：

| 适配器 | 接口 |
|---|---|
| `AnthropicProvider` | `POST {baseURL}/v1/messages`，请求头 `x-api-key`、`anthropic-version: 2023-06-01` |
| `OpenAICompatibleProvider` | `POST {baseURL}/chat/completions`，请求头 `Authorization: Bearer` |

内置预设（用户可以修改 Base URL 和模型名，也可以新增自定义服务商）：

| 预设 | 适配器 | Base URL | 默认模型（只是预填值，可修改） |
|---|---|---|---|
| Anthropic | Anthropic | `https://api.anthropic.com` | `claude-haiku-4-5` |
| OpenAI | OpenAI 兼容 | `https://api.openai.com/v1` | 留空，由用户填写 |
| DeepSeek | OpenAI 兼容 | `https://api.deepseek.com` | `deepseek-chat` |
| 硅基流动 | OpenAI 兼容 | `https://api.siliconflow.cn/v1` | 留空，由用户填写 |
| 阿里云百炼 | OpenAI 兼容 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 留空，由用户填写 |
| OpenRouter | OpenAI 兼容 | `https://openrouter.ai/api/v1` | 留空，由用户填写 |
| Ollama（本地） | OpenAI 兼容 | `http://localhost:11434/v1` | 留空，不需要 Key |

- 统一参数：`temperature = 0`，`max_tokens` = 输入长度估算值的 2 倍再加 1024，上限 16000。
- 请求超时 120 秒。
- 设置页提供“测试连接”按钮：发送一个很短的请求，显示成功、Key 无效、模型不存在或网络错误。
- 网络层定义为协议 `HTTPClient`，测试时注入假实现，**测试中不会真的调用任何 API**。

### 8.3 提示词

系统提示词（英文写，模型遵循效果更好；代码里作为常量）要表达以下约束：

1. 你是 Markdown 排版助手。只调整结构：标题层级、段落拆分与合并、列表、引用、强调、表格、空行。
2. **绝对不要**增加、删除、改写、翻译任何文字。标点只允许为了 Markdown 语法做最小调整。
3. 形如 `⟦TN:数字⟧` 的占位符必须原样保留，位置不变，不能增删。
4. 不要给原文没有的内容加标题；只有原文本来就像标题的短行才能变成标题。
5. 只输出排版后的 Markdown，不要解释，不要用代码围栏把结果包起来。

- 如果模型仍然在输出外层包了 ```markdown 围栏，程序自动剥掉。
- 设置里允许用户填写“额外要求”（例如“列表一律用 `-`”），追加在系统提示词末尾。
- 排版选中内容时，额外告诉模型“这是一篇文档中的片段，不要加文档级标题”。

### 8.4 内容保护（Protector）

以下内容在发送前替换为 `⟦TN:n⟧` 占位符，返回后原样还原：

- frontmatter（整块）
- 代码块（整块，包括围栏）
- 行内代码
- 链接和图片里的 URL 部分（链接文字保留，交给模型）
- 裸 URL

这保证了代码和链接 100% 不会被改动。

### 8.5 内容校验（ContentGuard）

1. 用 swift-markdown 把原文和结果都转换为纯文本（去掉所有 Markdown 语法）。
2. 归一化：去掉所有空白字符和 Unicode 标点（`P*` 类别），英文统一小写。
3. 对两个字符序列做差异比较（`CollectionDifference`），把连续的插入和删除合并成“改动片段”。
4. **通过条件**：所有改动片段的长度都 ≤ 2 个字符，且改动的字符总数 ≤ 原文长度的 1%。这样能容忍去掉有序列表的编号这类结构性变化，同时抓住任何真正的增删改。
5. 不通过时，把改动片段映射回原文中的句子，在对比窗口里列出来。
6. 差异计算前先比较长度：如果长度相差超过 10%，直接判为不通过，不再计算，避免在差异很大时耗时过长。

### 8.6 对比窗口

以 sheet 形式挂在主窗口上，最小 960 × 640，可以调整大小。

```
┌───────────────────────────────────────────────────────────┐
│  ✓ 文字内容未改动 · 调整了 6 处结构        [放弃]  [接受 ⏎] │  ← 顶部栏（26 上为玻璃材质）
├────────────────────────────┬──────────────────────────────┤
│  原文                       │  排版后                       │
│  （concealAll 渲染）         │  （concealAll 渲染）          │
│                            │ ▎变为标题                      │
│                            │ ▎变为列表                      │
└────────────────────────────┴──────────────────────────────┘
```

- **两栏都是渲染后的效果，不显示任何 Markdown 符号。**
- 两栏同步滚动：按块对齐，而不是按像素对齐。
- **块标记**：排版后一栏里，结构发生变化的块左侧画一条 2pt 的强调色竖线，旁边用小字标注变化类型：“变为标题”“变为列表”“变为引用”“变为表格”“拆分段落”“合并段落”“新增强调”。
- 块对齐算法（BlockDiff）：把两边的块按归一化后的纯文本做序列比对；一对一匹配且类型不同的块，标“变为 X”；一个原文块对应多个结果块，标“拆分段落”；多对一，标“合并段落”；类型相同但多了粗体或斜体，标“新增强调”。
- **校验通过**：顶部显示绿色的“✓ 文字内容未改动 · 调整了 N 处结构”，“接受”是默认按钮（回车触发）。
- **校验不通过**：顶部显示橙色警告“AI 可能改动了文字内容”，并在下方展开改动句子列表；“放弃”是默认按钮；“接受”按钮隐藏在“仍要接受…”这个文字链接后面，点击后需要再确认一次。
- **结构没有任何变化**：不打开对比窗口，只在编辑器顶部短暂提示“已经很整齐了，无需调整”。
- 按 `Esc` 等同于“放弃”。

### 8.7 状态与错误

- 请求进行中：工具栏的 AI 按钮变为进度指示，编辑器保持可编辑。如果请求期间文本被修改，请求结果作废，并提示“内容已变化，请重新排版”。
- 可以用 `Esc` 或再次按 `⌘⇧L` 取消。
- 错误统一显示在编辑器顶部的横幅里，提供可操作的按钮：

| 错误 | 提示 | 按钮 |
|---|---|---|
| 没有配置服务商 | 先设置一个 AI 服务商 | 打开设置 |
| 401 / 403 | API Key 无效或没有权限 | 打开设置 |
| 404（模型不存在） | 找不到模型“xxx” | 打开设置 |
| 429 | 请求太频繁或额度不足 | 重试 |
| 超时或网络错误 | 网络连接失败 | 重试 |
| 占位符缺失或重复 | AI 返回的结果不完整 | 重试 |

## 10. 其他功能

### 10.1 侧边栏与标签页

- **点击文件夹树中的笔记**：如果已经打开，切换到对应标签；否则新增一个标签，插入在当前标签之后。
- **置顶**：右键菜单“置顶”，或把标签拖到“置顶”分区。置顶的笔记不出现在“已打开”里。置顶笔记不能关闭，只能取消置顶。
- “已打开”分区可以拖拽排序；`⌘W` 关闭当前标签；关闭后切换到相邻的标签。
- `⌃Tab` / `⌃⇧Tab` 按“置顶 + 已打开”的顺序切换；`⌘1`–`⌘9` 跳到第 N 个。
- 重新启动应用后，恢复之前打开的标签、顺序和当前标签。
- 没有打开任何笔记时，编辑区显示空状态：一行用三级文字颜色显示的“按 ⌘N 新建笔记，或按 ⌘P 打开”。
- 首次启动（没有笔记库）：窗口中间显示欢迎界面，标题“选择一个文件夹作为笔记库”，按钮“选择文件夹…”和“新建笔记库…”。

### 10.2 快速打开（`⌘P`）

- 窗口顶部居中的浮动面板，宽 560pt，玻璃材质。
- 输入框为空时列出最近打开的 10 篇笔记；输入时对标题和路径做模糊匹配（按子序列匹配打分，连续匹配和词首匹配加分），最多显示 50 条。
- 上下方向键选择，回车打开，`Esc` 关闭。
- 输入内容如果没有匹配，最后一行显示“新建笔记‘xxx’”。

### 10.3 标签

- 行内标签：`#` 后面跟字母、数字、`_`、`-`、`/`，支持中文；`#` 前面必须是行首或空白；代码、链接、标题符号中的 `#` 不算标签。纯数字（例如 `#123`）不算标签。
- frontmatter：`tags: [a, b]` 或 YAML 列表形式都支持。v1 用简单的行解析处理这两种格式，不引入 YAML 库。
- 支持嵌套标签 `#工作/周报`：侧边栏按层级显示，点击父标签时包含所有子标签的笔记。
- 点击侧边栏的标签：侧边栏切换为该标签的笔记列表，顶部显示“#标签名”和返回按钮。

### 10.4 全文搜索（`⌘⇧F`）

- 侧边栏顶部的搜索框获得焦点，输入时侧边栏切换为搜索结果，`Esc` 或清空搜索框后恢复原来的分区。
- 每条结果显示笔记标题和一行摘要，关键字高亮（FTS5 的 `snippet()`）。
- 查询长度 ≥ 3 个字符：用 FTS5 trigram 搜索，按 `bm25` 排序。
- 查询长度为 1–2 个字符：对 `notes.title` 和 `notes.body` 用 `LIKE` 搜索（中文单字、双字词常见）。
- 查询中含 `#xxx` 时，只在带有该标签的笔记中搜索。
- 输入防抖 120ms。
- 打开搜索结果后，在编辑器中高亮所有匹配项并滚动到第一个。

### 10.5 粘贴与拖入图片

- 支持粘贴板里的图片数据（PNG、JPEG、TIFF、HEIC），以及拖入或粘贴的图片文件。
- 保存位置：`<笔记库>/attachments/`，文件名为 `yyyyMMdd-HHmmss-xxxx.<扩展名>`（`xxxx` 为 4 位随机字符）。
- 图片数据如果是 TIFF，转为 PNG 保存；如果是文件，保持原格式直接复制。
- 在光标处插入 `![](attachments/文件名)`，路径相对于笔记库根目录；编辑器和导出解析图片路径时，先按相对于当前笔记的路径找，找不到再按相对于笔记库根目录找（兼容 Obsidian 的习惯）。
- 显示：按显示宽度用 ImageIO 生成缩略图，缓存上限 64MB。

### 10.6 导出 PDF（`⌘⇧E`）

- 流程：swift-markdown → HTML（优先用 swift-markdown 自带的 `HTMLFormatter`，不满足需求时自己写一个 `MarkupVisitor`）→ 套用内置 CSS → 离屏 `WKWebView` 加载（`loadFileURL` 允许读取笔记库目录，以便显示图片）→ 用 `printOperation(with:)` 输出分页 PDF → 保存面板。
- CSS 与 9.3 节的排版一致，纸张 A4，页边距 20mm，代码块和图片避免跨页断开（`break-inside: avoid`）。
- 导出 PDF 时强制使用浅色样式。
- frontmatter 不导出。
- 导出完成后立即释放 `WKWebView`。

### 10.7 自动更新

- Sparkle 2，更新源 `appcast.xml` 放在 GitHub Releases（或 GitHub Pages）。
- 用 EdDSA 签名更新包，私钥只存在 GitHub Actions 的 secret 里。
- 设置中提供“自动检查更新”开关（默认开）和“立即检查”按钮；菜单栏“ToastNote → 检查更新…”。

### 10.8 设置窗口（`⌘,`）

| 页面 | 内容 |
|---|---|
| 通用 | 当前笔记库及“更换…”，启动时打开上次的笔记库，外观（跟随系统 / 浅色 / 深色） |
| 编辑器 | 正文字号（13–20pt），正文最大宽度（600–900pt），拼写检查开关 |
| AI | 服务商列表（新增、删除、选择当前服务商），每个服务商的 Base URL、模型名、API Key（安全输入框）、“测试连接”，额外要求（多行文本） |
| 更新 | 自动检查开关，立即检查，当前版本号 |

| App（手动） | 每个阶段附一份手动验证清单，包括中文输入法组字、光标移动时符号显示与隐藏、深浅色模式、macOS 14 与 26 的外观 |

- 测试中禁止访问网络，禁止读写用户的真实笔记库。
- 性能测试：生成一个 1000 篇笔记的测试库（脚本放在 `scripts/make-test-vault.sh`），用于第 3 节的资源预算测量。
- CI：GitHub Actions 的 macOS runner 上运行 `swift test` 和 `xcodebuild build`。

## 12. 后续阶段：AI 自动关联（v1 不实现，只预留）

目标：AI 读完所有笔记，自动发现笔记之间的关系，在笔记底部显示“相关笔记”，并提供关系图谱视图。用户不需要手动写 `[[链接]]`。

初步方案（届时另写 spec）：

1. **粗筛**：把每篇笔记切块后计算语义向量，存入 `embeddings` 表，用余弦相似度找候选相关笔记。向量来源可以替换：
   - 默认：BYOK 的 OpenAI 兼容 `/v1/embeddings` 接口（国内服务商普遍支持，本地 Ollama 也可以）。
   - 可选：系统 NaturalLanguage 框架的 `NLContextualEmbedding`。它不属于 Apple Intelligence，但需要从苹果服务器下载模型，**国行环境下能否下载需要实测**；能用时作为免费、离线的选项。
2. **精判**：只把候选笔记对的摘要发给大模型，让它判断关系是否成立并给出一句话说明。
3. **展示**：笔记底部的“相关笔记”区，以及一个关系图谱窗口。

v1 为此预留的内容：`embeddings` 表、`AIFormatKit` 中的服务商配置可以复用、`IndexKit` 的增量更新机制。

## 14. 风险与待验证事项

| 风险 | 应对 |
|---|---|
| 用 `.null` 字形隐藏符号时，光标移动、选择、复制的行为可能不符合直觉 | M2 先做一个最小原型专门验证：光标在隐藏符号附近的左右移动、双击选词、复制时是否包含隐藏符号（应包含） |
| TextKit 1 与 macOS 26 的新行为不兼容 | 在 macOS 14 和 26 上都做手动验证；如有严重问题，记录在案后再评估 TextKit 2 |
| 中文输入法组字期间重新上样式导致候选框错位 | 7.4 节的规则，加专门的测试和手动验证 |
| 小模型不遵守“不改字”的约束 | ContentGuard 兜底；`temperature = 0`；文档中建议用户使用能力较强的模型 |
| 没有 Apple 开发者账号，无法公证 | 发布流程支持“未签名构建”，README 说明首次打开需要右键 → 打开；有账号后启用公证步骤 |
| `swift-markdown` 的 `HTMLFormatter` 功能不足 | 退回到自己写的 `MarkupVisitor`，工作量可控 |
| `NLContextualEmbedding` 在国行不可用 | 后续阶段默认使用 BYOK 的向量接口，本地方案只是可选项 |
